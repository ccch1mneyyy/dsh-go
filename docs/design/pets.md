# dsh-go 宠物系统设计

> 2026-10-25。本文是宠物系统实现规格的正式版，相对规格改过的地方集中列在 §12。
> 素材：Deepy 小鲸鱼（Clawd on Desk 主题包）、鲸娘（dshtui.com 序列帧），源文件在 `app/tool/pet_src/`，作者与授权见仓库根目录的 `ASSETS.md`。

## 0. 结论

- **协议照 Clawd on Desk。** 状态名、事件对应、优先级、一次性与持续态的划分都沿用 Clawd，两套素材因此可以直接用。Codex Pet 留到第二期，作为导入格式。
- **宠物是状态指示器，不是养成游戏。** 它只表达 agent 在干什么、有没有事等你，不设饥饿、好感之类的数值，不主动调模型、不独立联网；「问一句」由用户触发，复用聊天发送链路。dsh-pet 每 5 分钟调一次模型说话，是我们明确不做的反例。
- **一屏一个吉祥物。** 宠物站在活动条上时接管鲸尾；空状态里的静止鲸尾在宠物开启时也隐藏。
- **同一件事只提醒一次。** 宠物在屏幕上时，它的气泡替代现有的玻璃横幅。当前正在看的对话不冒气泡，只做动作。后台照常发系统通知。
- **不挡事。** 命中区只算身体，避开「回到底部」按钮，输入框弹出层打开时让位，列表底部为宠物留出高度，悬浮窗空闲时原地变淡。
- **像素必须清楚。** 每个美术像素对应整数个**物理**像素，位置也对齐物理像素。尺寸按身体高度分小、标准、大三档。
- **悬浮窗做成可降级的可选项。** 默认关闭，用户打开时再申请权限。被拒、被系统藏起、被 ROM 杀掉，都退回 App 内宠物加系统通知，不报错。

### 1.2 落到我们身上的原则

1. **反应多，主动少。** 宠物的动作几乎都是对 agent 事件或用户触摸的回应。主动行为只有待机小动作和游走，而且很稀疏。
2. **只在有事时说话。** 气泡只用于做完、出错、等你确认或回答这四类事，且同一件事只说一次。没有闲聊，没有提醒你回来。
3. **随手能藏，处处能关。** 长按菜单里有「藏起来 1 小时」。悬浮窗拖到底部就关，设置里一键「不显示」。
4. **不挡事。** 不挡输入框、按钮和正文，不抢焦点，不劫持触摸。
5. **小而清楚。** 标准档身体高约 30dp，像素边缘清晰。
6. **省电是默认行为。** 不在屏幕上就不画，待机时停在静帧，只在帧号变化时重绘。

## 2. 产品规则

### 2.1 入口与默认值

- 设置 › 主题里加一组「宠物」，点进去是宠物页。宠物页包含：
  - 选宠物：Deepy 小鲸鱼、鲸娘、不显示，带实时预览；
  - 大小：小、标准、大；
  - 安静模式；
  - App 外显示；
  - 作者与来源，作为页底一行小字。
- 默认值：Deepy 小鲸鱼、标准大小、站在输入框上。安静模式关，App 外显示关。
- 第二期再做导入 Clawd on Desk 主题 zip 和 Codex Pet zip，§3.5 先把映射定好。

### 2.2 站位（perch）

- **站位**是聊天页里一组水平的胶囊上沿：输入框，以及它上方的活动条、待办条、目标条。各个胶囊用 key 向 `PetPerch` 注册表上报自己。宠物永远站在**当前最上面那条可见胶囊**的上沿，脚踩着边。
- **脚线**：`anchor.baseline` 乘以缩放倍数后，必须落在胶囊上沿上，误差不超过 0.5 逻辑像素。跟随时用 `CompositedTransformFollower` 挂在胶囊的 `LayerLink` 上，不要逐帧读 `GlobalKey` 的矩形。逐帧读会晚一帧，键盘升起的动画里看得出脚离开了边。
- **换站位**：条出现或消失时，宠物播 hop 跳到新的上沿，水平位置按比例保持。hop 的时长和曲线走 `AppMotion`。
- **默认水平位置在左边 1/4 处。** 右侧是「回到底部」按钮和待确认胶囊的位置（`chat_list.dart`，右下、输入框上方 12dp）。
- **禁区**：「回到底部」按钮或胶囊可见时，它的矩形左右各外扩 8dp，作为禁区。宠物不站进禁区，拖进去松手会吸附到禁区外最近的位置。按钮出现时如果宠物正好在禁区里，它会走开。
- **拖动**：拖动时播 drag 动画，松手后吸附到当前站位，位置按比例存起来。
- **让位**：以下几种时候宠物淡出，不占命中区：斜杠面板、@ 提及、附件面板或语音面板打开时，多选或编辑模式，只读对话。这些弹出层关闭后再淡入。
- **不挡正文**：宠物开启时，聊天列表的底部内边距加上宠物在站位之上的高度，即 `contentBox` 顶到 `baseline` 的距离乘以缩放倍数。这样滚到底时，最后一行字不会被宠物盖住。
- **命中区**：只算当前动画的命中框（§3.2 的 `hitBoxes`），框外的触摸全部穿透给下面的列表和按钮。

### 2.3 一屏一个吉祥物

- 宠物开启并站在活动条上时，活动条里的鲸尾隐藏，鲸尾的位置收起，文字左移，左右内边距保持对称。宠物的动作接替鲸尾表达状态。
- 宠物开启时，空状态里的静止鲸尾（`empty_state.dart:170`）也隐藏。宠物本身就站在输入框上，不需要两条鲸鱼。
- 宠物关闭或藏起来时，鲸尾原样回来。

### 2.4 待机、游走、睡觉

- **待机**：按 `idlePool` 的权重和时长随机播放待机动作。Deepy 的 `idle-follow.svg`（眼睛跟随鼠标）在手机上不用，待机用 `idle.apng`。
- **游走**：
  - 平均 2 分钟一次，间隔在 45 秒到 5 分钟之间随机，只在空闲时触发；
  - 沿当前站位走一小段，不进禁区，不越出胶囊两端，按方向翻转；
  - 输入框有焦点、列表正在滚动、或者有气泡在显示时，都不游走。
- **睡觉**：处于空闲状态，并且 App 里 60 秒没有任何触摸时，宠物入睡。任何触摸或事件都会叫醒它：先播 waking，再进入应有的状态。
- **减弱动效**：系统关闭动画时，`AppMotion` 的时长为零。这时宠物停在每个状态的首帧，换站位直接瞬移，不游走，不播 hop。

### 2.5 互动（App 内）

| 手势 | 反应 |
|---|---|
| 单击身体左半、右半 | 分别播 `tapLeft`、`tapRight` 反应，播一遍后回到原状态 |
| 1.1 秒内连点 3 下 | 挠痒痒（`tickle`）；连点期间继续点会延长 |
| 按住并移动超过 6dp | 拖动，播 `drag`，松手后吸附 |
| 长按 | 小菜单：换宠物、藏起来 1 小时、宠物设置 |
| 宠物在 notification 状态时单击 | 不播戳的反应，改为执行「去看看」：当前对话就滚到待确认的卡片，别的对话就打开那个对话 |
| 宠物在睡觉时单击 | 只叫醒，不播戳的反应 |

挠痒痒从规格的「连点 4 下」改成「1.1 秒内 3 下」，和鲸娘原页一致。手机上的目标很小，连点 4 下容易点偏。

### 2.6 气泡提醒（App 内）

现有的提醒分三路（`notify_state.dart` 的 `deliveryFor`）：正在看的对话不提醒，前台时出玻璃横幅，后台时发系统通知。宠物接进来以后：

| 场景 | 现在 | 有宠物以后 |
|---|---|---|
| 事件发生在正在看的对话里 | 不提醒 | 不冒气泡，宠物只做动作：attention、error、notification。待确认事项继续由「回到底部」胶囊承担；单击宠物等同于点那个胶囊 |
| 前台，别的对话，聊天页可见，宠物可见，非安静模式 | 玻璃横幅 | **宠物气泡替代横幅**，同一件事不出两次 |
| 前台，别的对话，但不在聊天页、宠物藏起来或安静模式 | 玻璃横幅 | 不变 |
| 后台 | 系统通知 | 不变；悬浮窗开着时另见 §2.7 |

为此 `AlertDelivery` 要加一个 `pet` 值。条件全部满足时，原本该出横幅的提醒改走宠物。

气泡规则：

- **内容**：一行，正文只有四种：「做完了」「出错了」「等你确认」「等你回答」。别的对话的事件在前面加标题，写成「标题 · 做完了」。标题先过 `secret_mask`，超过 12 个字截断。
- **合并**：2 秒内来了多件事，合成一个气泡，例如「3 个对话做完了」。等你确认或回答的事优先显示，同时只保留一个待显示的气泡。
- **停留**：做完了 4 秒，出错了 6 秒，等你确认或回答 8 秒。确认或回答之前，宠物会一直保持 notification 动作。点按会提前收起；向上轻扫会收起，但不跳转。
- **点按**：打开那个对话，并滚到对应的审批卡或问题卡。
- **不提醒的事**：被停下的轮（`stopped`）、压缩完成、连接断开都不提醒。
- **可访问性**：气泡带 `liveRegion` 语义，读屏会念出来，能聚焦，也能点。宠物本体是装饰，不进语义树。因为气泡替代了横幅，它必须做到横幅原有的可访问性。

### 2.7 App 外悬浮窗

**什么时候出现**

- **默认模式「有事时显示」**：App 在后台，并且有对话正在跑或者有事等你时，悬浮窗出现。App 回到前台时它隐藏，舞台交还给聊天页上的宠物。
- **「一直显示」模式**：只要 App 不在前台就显示。
- **自动收起**：最后一件事结束 5 分钟后，如果没有新事件，悬浮窗收起。「一直显示」模式不自动收起。
- **其他情况**：灭屏时暂停；锁屏时系统本来就不显示这类窗口。敏感界面（例如权限对话框、银行 App）可以调用 `setHideOverlayWindows(true)` 把悬浮窗藏掉，这时我们等它重新可见，不报错，也不重复添加窗口。

**交互**

| 手势 | 行为 |
|---|---|
| 拖动 | 跟手移动，松手后吸附到最近的屏幕左边缘或右边缘，纵向位置记住 |
| 拖到屏幕底部中央的「×」 | 今天不再显示。这个「×」只在拖动时出现，和聊天头像的做法一样 |
| 单击 | 打开最相关的对话，见下文 |
| 长按 | 小菜单：今天不再显示、宠物设置 |
| 空闲 10 秒 | 原地变淡到 60% 不透明度，整只留在屏幕内，照常能点能拖，动画暂停；碰一下、新气泡、有结果或有请求时恢复 |

**最相关的对话**，按以下顺序取第一个：

1. 等你确认或回答的对话（等得最久的那个）；
2. 刚出错还没看过的对话；
3. 刚做完还没看过的对话；
4. 正在跑、最近有动静的对话；
5. 最近看过的对话。

由 Dart 端算好，随状态一起推给 Kotlin，Kotlin 只负责调用 `EntryActivity.openChat`。

**气泡**

- 文案和合并规则同 §2.6。悬浮窗气泡只显示标题，从不显示对话正文。
- 气泡是单独的一个小窗，显示期间可以点，收起后窗口移除。
- 位置和 App 内一致：放在**当前画面的上方**，即身体框并上当前动画的帧格，跳起来的身体、思考云、「!」都在气泡下面，不会钻到气泡后面。宁可比只按身体框高出一截（Deepy 的 happy 约 21 个美术像素，标准尺寸下约 80 物理像素），也不盖住宠物。横向仍是内侧边缘和身体对齐、朝屏幕中间伸，尾巴指向身体中线。换动画时气泡跟着新画面在 200ms 内平滑移过去，不跳。
- 上方放不下（贴在屏幕顶部时）就放到画面侧面、朝屏幕中间的一边，和身体中线等高，尾巴横着指回宠物；侧面也放不下才放到画面下方。任何情况下都在屏幕安全区内，不压状态栏和导航栏。实现见 `EdgeSnap.bubble`。
- **悬浮气泡仅在完整显示批准内容时提供「允许本次 / 拒绝」。** 2026-10-30 的「问一句」扩展取代原先一律不提供按钮的规则，具体边界见 §14。App 内气泡仍只打开对应卡片。

**与系统通知的关系**：系统通知照常发，数量不减。悬浮窗可见并且亮屏时，「做完了」和「出错了」这两类通知改为静默（`setSilent(true)`：不弹横幅、不响），因为悬浮窗气泡已经说过一遍了。「等你确认」和「等你回答」保持原样。这一条还没有实现，见 §12 第 5 条。

**行为边界**

- 悬浮窗不游走，只在原地播动作。在别的 App 上空走来走去就成了 Desktop Goose。
- 不抢焦点，不弹 Activity，不在别的 App 上自动展开任何东西。

### 2.8 安静模式与隐藏

- **安静模式**：只做动作，不冒气泡，App 内和悬浮窗都适用。原本该由宠物气泡承担的提醒，退回玻璃横幅或系统通知，提醒本身不会丢。
- **藏起来 1 小时**：期间不显示，鲸尾回来，提醒走原来的横幅；1 小时后自动出现。
- **今天不再显示**：只针对悬浮窗，到次日 0 点恢复。

### 2.9 网页模式

网页模式的聊天页里没有原生宠物。用户可以在网页里自己装 dsh-pet（风险见 §1.1 的对比表）。悬浮窗在两种模式下都工作，数据都来自同一个 `PetMood`。

### 2.10 尺寸

- 尺寸按**身体高度**定档，不按画布大小，这样两只宠物看起来一样大：

  | 档位 | 身体目标高度 |
  |---|---|
  | 小 | 22dp |
  | 标准 | 30dp |
  | 大 | 40dp |

  身体高度取 `contentBox.h`。
- 缩放倍数 `k` 的定义是：每个美术像素占多少个**物理像素**。像素画包要求 `k` 为整数，`k = max(1, round(目标dp × devicePixelRatio ÷ contentBox.h))`。
- 宠物的左上角和脚线都对齐到物理像素。
- 悬浮窗和 App 内用同一档位。

### 3.2 pack.json（schema 1）

下面是 `deepy-whale` 的实际内容（`animations` 只列一段，`frames` 截短）。完整格式、每个字段的解析规则以 `app/lib/pets/pet_pack.dart` 为准，生成工具是 `app/tool/make_pet_pack.py`。

字段说明（相对规格新增或改动的字段标 ★）：

- ★ **`scale`**：源图相对逻辑像素的倍率，总是写出来。缩回 1 倍无损才存 1 倍，否则保留原倍率。
  - 鲸娘是 1。
  - Deepy 是 5：身体画在半像素上，呼吸和压扁按 1/5 像素变化，缩回 1 倍会丢细节。
- ★ **`anchor`**：`baseline` 是脚线，即身体最低不透明行的下沿，放到站位胶囊的上沿；`x` 是身体水平中心，也是镜像轴。
  - Deepy 是 48 和 28，不是 Clawd 主题写的 48.5 和 27。48.5 是阴影的中线，阴影落在脚线下方，压在胶囊上做接触阴影；27.75 是待机各帧质心的平均。
  - 鲸娘是 60 和 35.5。
- ★ **`cols`**：一张图里每行放几帧，默认等于帧数，也就是单行横条。约束：
  - 每张图的任一边不超过 4096 物理像素；
  - 单段动画解码后建议不超过 8 MB。Deepy 有 6 段例外（8.8～12.9 MB），保持 5 倍无损；
  - Deepy 一段最多 68 帧：5 倍时单行宽 17,680 像素，会超过很多 GPU 的纹理上限。所以保持 5 倍，用网格排列（`cols`）并去重。
- ★ **`box`**：每段动画的帧格只裁到这段动画实际有像素的范围，`box` 是帧格贴回画布的位置（逻辑像素）。`frameW = box.w × scale`。
- **`frames`**：每项是 `{i, ms}`，`i` 指向图里的第几格。相同的帧只存一格，靠 `i` 重复引用。Deepy 是统一 20fps，持帧多，去重能省下不少。
- ★ **`hitBoxes`**：结构照 Clawd：`default`、`wide`、`sleeping` 三类框，加上 `byAnim` 单独给框，单位是逻辑像素。两个包的框都从帧里量出来，不照搬主题：
  - 每帧只取最大的一块连通区域当身体，思考云、Zzz、音符这类脱离身体的道具不算；
  - 一段动画里至少 25 % 时间是身体的格子，才算进这段的身体框；
  - 超出 `default` 较多的动画进 `wideAnims`；离 `default` 太远或被拎起来的，在 `byAnim` 里单独给框；
  - 每段动画查到的框至少框住它 90 % 的身体。
  - 查找顺序：`byAnim` → `sleepingAnims` → `wideAnims` → `default`。
- ★ **`idlePool`**：随机待机，是对象：
  - `everyMs` 是插播间隔：平均 120 秒，最短 45 秒，最长 300 秒，只在空闲且可见时计时；
  - `anims` 是待机池，每项带时长和权重。
  - 基础待机循环在 `states.idle[0]`，不放进池子。
  - 时长都是整 2 遍：Deepy 照搬 Clawd 的 `idleAnimations.duration`，鲸娘按原页的循环时长算。
- ★ **`bonus`**：attention 时按 `chance` 的概率改播彩蛋动画。鲸娘的 `smile-hearts`、`thumbs-up` 放在这里，概率 0.2。Deepy 没有彩蛋，写 `{}`。
- ★ **`roam.faces`**：美术本身朝哪边，取 `"left"`、`"right"` 或 `"front"`。它取代含义不清的 `flip`。
  - `left`、`right`：往反方向走时以 `anchor.x` 为轴镜像。Deepy 的 `roamFlipAssets: true` 表示美术朝左，所以是 `left`。
  - `front`：正面，不镜像。鲸娘是 `front`，镜像会把发花和尾巴换边。
- **`timings`**：
  - Deepy 从 Clawd 主题照搬，只去掉 notification 的 `autoReturn`。
  - 鲸娘按原页事件表的保持遍数换算：error 1 遍，1480ms；happy 2 遍，3040ms；carrying 2 遍，2240ms；waking 1 遍，1880ms；notification 3 遍，2640ms，只作 `minDisplay`。
  - 鲸娘的压缩动画在原页里一直保持到下一个事件，没写遍数，所以 sweeping 的 `minDisplay` 取 1 遍，1740ms。
  - notification 不设 `autoReturn`，见 §4。
  - working / thinking 的 1000 是去抖，sweeping `autoReturn` 的 300000 是保险上限，两个包一样。
- 状态名一律用 Clawd 的。动画名用包自己的：鲸娘的反应叫 `poke-left`、`poke-right`、`tickle`、`drag`，游走叫 `swim`。
- `author`、`license`、`source` 必须如实填写，宠物页底部原样显示，见 §9。两只都是 DSH-TUI 的吉祥物，作者与授权见仓库根目录的 `ASSETS.md`。

### 3.3 运行时加载

- App 内同一时间只解码当前这一段，加上常驻的 `states.idle[0]`；其余按需解码，用 LRU 缓存最多 2 段。Deepy 全部解码约 139 MB，不能整包预解码。
- 悬浮窗在 Kotlin 侧按显示尺寸降采样解码，比如 Deepy 降到每逻辑像素 2 个像素，最大一段从 12.9 MB 降到约 2.1 MB。
- Flutter 端和 Kotlin 端读的是同一份 `app/assets/pets/<id>/`，Kotlin 从 APK 的 `flutter_assets` 里读。

## 4. 状态归约 `PetMood`

`PetMood` 是 Dart 纯函数，只实现这一份，可单测。悬浮窗的 Kotlin 端只接收归约后的结果，不重复实现。

### 4.1 输入与范围

输入：所有主机上所有对话的运行快照，包括 `runActivityOf`、待确认事项、`AlertKind` 事件流、子代理数和压缩状态；另外还有当前在看的对话，以及最近一次触摸的时间。

**站在谁身上，就替谁说话：**

| 宠物在哪 | 基础状态取自 |
|---|---|
| 活动条上，表示当前对话在跑 | 当前对话（接管鲸尾，必须和活动条一致） |
| 输入框上，表示当前对话空闲 | 全局：所有对话按优先级取最高 |
| 悬浮窗 | 全局 |

档位永远按全局计数。气泡不受范围限制：任何对话的事件都可能冒气泡，规则见 §2.6。

### 4.2 信号到状态

| 宠物状态 | 我们的信号 | 类型 |
|---|---|---|
| idle | 范围内没有在跑的轮 | 持续 |
| thinking | `ActivityKind` 为 waiting、thinking，或者在重试 | 持续 |
| working | `ActivityKind` 为 tool、writing。按全局在跑的对话数分档：1、2、3 个及以上 | 持续 |
| juggling | 有子代理在跑。按子代理数分档：1、2 个及以上 | 持续 |
| sweeping | 正在压缩（compaction） | 持续，`autoReturn` 300 秒兜底 |
| notification | 有待确认或待回答的事（approval、question） | **持续，直到处理完** |
| attention | `AlertKind.done`，并且 1.5 秒内同一对话没有开始新的一轮 | 一次性 |
| error | `AlertKind.failed` | 一次性 |
| carrying | 预留：上传或导入文件 | 一次性 |
| sleeping | 空闲，并且 60 秒没有触摸 | 持续 |
| waking | 睡着时被触摸或来了事件 | 一次性，`wakeMs` |
| roam | 空闲期间随机触发 | 一次性 |

下面几种情况不改变状态：`ActivityKind.stopping` 保持原状态；`AlertKind.stopped` 安静地回到 idle，既不庆祝也不报错；压缩完成不庆祝；连接断开或引擎重启不进 error。

### 4.3 优先级与时长

- **优先级**照 Clawd：error 8 > notification 7 > sweeping 6 > attention 5 > carrying 4 = juggling 4 > working 3 > thinking 2 > idle 1 = roam 1 > sleeping 0。多个对话合并时取最高的；并列时取最近发生的那个。
- **一次性态**：至少显示 `minDisplay`，到 `autoReturn` 后回到当前的持续态。低优先级的新状态不能打断高优先级的一次性态。
- **完成去抖**：done 事件先压住，1.5 秒内同一对话有新一轮开始就丢掉，没有才升成 attention。这样目标续跑时不会每轮放一次彩纸。dsh-pet 和 Clawd 都单独处理了这种情况。
- **忙碌档**：升档立即生效，降档要等档位持续 5 秒低于当前档才降。thinking 和 working 之间互相切换时，各自至少显示 `minDisplay`，Deepy 是 1 秒。
- **互动反应**：在 idle、thinking、working、juggling、sleeping 之上临时播放，播完回到原状态；睡着时先播 waking。在 notification 状态下，单击改为「去看看」，见 §2.5。

### 4.4 输出

`PetMood` 的输出包括：

- `state`：状态枚举；
- `tier`：档位；
- `bubble?`：气泡，包含种类、标题、目标对话和合并数量；
- `target?`：最相关的对话，悬浮窗点击时用。

具体类型见 `app/lib/pets/pet_overlay_bridge.dart`。通道 `dsh/pet_overlay` 推送的内容是 `{state, tier, bubble?, target?, packId, size, quiet}`。

## 5. 渲染

- **像素画包**（`pixelArt: true` 且 `scale: 1`）：最近邻采样，`FilterQuality.none`，按 §2.10 的整数 `k` 绘制，左上角对齐物理像素。
- **高倍率包**（`scale > 1` 或 `pixelArt: false`）：用 `FilterQuality.medium`，`k` 不要求是整数，但锚点仍然对齐物理像素。
- 用 `CustomPainter` 或 `RawImage` 画当前帧，只在帧号变化时重绘，不要每个 vsync 都重绘。
- 宠物所在的子树用 `RepaintBoundary` 隔开，宠物动起来时不能让聊天列表跟着重绘。
- 浅色和深色主题下都不给宠物描边、不调色。气泡用现有的玻璃表面令牌，跟随 App 字号。

## 6. 悬浮窗（Kotlin）技术规范

### 6.1 窗口

| 项 | 规定 |
|---|---|
| 类型 | 默认用 `TYPE_APPLICATION_OVERLAY`，需要 `SYSTEM_ALERT_WINDOW`。用户已为手机操控开了无障碍服务时，复用 `TYPE_ACCESSIBILITY_OVERLAY`，不需要额外授权 |
| 无障碍宿主 | API 30+ 从已连接服务派生独立 display/window context，由当前连接提供 overlay token。添加失败冷却 60 秒，服务实例变化可重新尝试；冷却期间仅在 `canDrawOverlays` 明确允许时回退应用悬浮窗。延迟移除仍未完成时等待轮询，不在下一帧回调中自旋 |
| 标志 | `FLAG_NOT_FOCUSABLE`、`FLAG_LAYOUT_NO_LIMITS`；**不加** `FLAG_NOT_TOUCHABLE` |
| 大小 | 平时窗口等于宠物 `hitBoxes.wide` 并上待机首段动画的帧格，再乘以 `k`，不是整个画布，更不铺满屏幕。命中框量的是身体，会漏掉待机图最下面一行（鲸娘的轮廓、Deepy 的阴影），所以要并上帧格。超出窗口的特效会被裁掉，这是可以接受的 |
| 被拎起 | 拖动时宠物换成 `drag` 反应的姿势，身体整个被提起来：Deepy 的 `react-drag` 身体顶到 y 4.4，比宽命中框的上沿高 13.6 个美术像素，标准尺寸下约 52 物理像素，按平时的窗口会被截掉半个身子。所以按下开始拖时，窗口一次性长到「平时窗口 ∪ drag 帧格」，松手后换回平时的画面再缩回去；如果那一段的图要重新解码，等新画面出来再缩。长大和缩回都以平时窗口的左上角为原点，宠物在屏幕上不动。拖动中保证长大后的整个窗口留在屏幕和状态栏、导航栏之内；松手的吸附仍按手指带着平时窗口走到的位置计算，规则不变。实现见 `PetFrames.kt` |
| 跳起和打字 | attention、waking、working 三个状态的首段动画（两只宠物都是 happy、waking、typing）播放时，窗口临时长到「平时窗口 ∪ 该段帧格」，换成别的画面就缩回，原点同上，宠物不动。Deepy 的 happy、waking 跳起来比平时窗口高 13–14 个美术像素，typing 的电脑向左伸出 8 个；鲸娘的三段向左、向上超出 1–8 个。取并集，所以只朝超出的方向长：Deepy 的 typing 只向左长 8 个、向上长 1 个（顶上一行要的），右边和下边不动。typing 一跑就是一整轮，长出去的部分会一直挡住下面的点击，所以只长需要的方向。吸附时按「平时窗口 ∪ 三段的窗口」留位置，长大的窗口在任何吸附位置都在屏幕内，不压状态栏和导航栏；代价是贴左边时 Deepy 离边多出约 8 个美术像素，贴顶时低约 14 个。其余状态的特效（思考云、Zzz、音符）仍按上一行裁掉 |
| 移动 | 窗口位置只由我们自己动：拖动时每个触摸事件都按手指直接算出位置，松手吸附用自己的动画。窗口的大小和位置在同一次布局里一起变时（拎起长大、松手缩回、三段动画长大），系统默认会放约 0.4 秒的移动动画，其间不理后面的位置更新：拎起后宠物最多落后手指 220 像素、440 ms，再一下跳过去。所以每个悬浮窗都关掉它：API 34 起 `setCanPlayMoveAnimation(false)`，更早的系统设同一个私有标志 `PRIVATE_FLAG_NO_MOVE_ANIMATION` |
| 穿透 | 不做像素级穿透。Android 12 起，带 `FLAG_NOT_TOUCHABLE` 的不可信悬浮窗，如果窗口 alpha 不低于 0.8，系统会拦掉落在它下面的触摸，宠物又不能做成半透明。所以窗口要做小，窗口内的触摸都由我们自己处理。也因为这一条，不能一开始就按所有姿势的最大包围盒把窗口开大：透明的部分一样会挡住下面 App 的点击，限制可触摸区域或拆成两层窗口都绕不开（判定看的是窗口框，不是可触摸区域）。只在拖动时（手指本来就按在宠物上）和上一行那三段动画播放时临时长大，而且只朝需要的方向长 |
| 气泡 | 单独开一个小窗，可以点，收起即移除 |
| 动画 | 用 `Choreographer` 驱动，但只在帧号变化时 `invalidate` |

### 6.2 省电

- 灭屏、空闲变淡、App 回到前台时，完全停止绘制（变淡本身的 0.4 秒淡出除外）。
- 待机时不靠降帧来省电，因为降帧会让动作发卡。做法是停在静帧，每隔 8 到 15 秒完整播一次待机小动作。
- 有事件时按原速播放。
- 5 分钟无事自动收起，见 §2.7。

### 6.3 进程与前台服务

- Flutter 引擎被缓存，不随 Activity 销毁（`MainActivity.shouldDestroyEngineWithHost = false`）。所以只要进程还在，`PetMood` 就在跑。
- 本机引擎在跑时，悬浮窗挂在 `DshService` 上。只连远程主机时，用悬浮窗自己的前台服务，类型是 `specialUse`（manifest 里已经声明了 `FOREGROUND_SERVICE_SPECIAL_USE`）。
- 当前 `targetSdk` 是 28。Android 15 对「凭 SAW 在后台启动前台服务」的收紧按 target 生效，眼下不受影响，但将来提高 target 时必须先保证悬浮窗可见。在 `docs/architecture.md` 的 target 升级清单里记一笔。

### 6.4 权限引导

1. 用户打开「App 外显示」时：如果无障碍服务已开，直接用无障碍悬浮窗，不再申请权限；否则跳转 `ACTION_MANAGE_OVERLAY_PERMISSION`。
2. 从浏览器或文件管理器侧载安装、并且是 Android 13 及以上的机器：悬浮窗属于「受限设置」，Android 15 CDD 明确列入。按受限设置的引导，先打开应用信息页，允许受限制的设置。
3. vivo 和 OriginOS 另有自己的悬浮窗开关，默认关闭。`ACTION_MANAGE_OVERLAY_PERMISSION` 在部分机型上只跳到总列表，入口位置要真机核实。旧版系统上 `canDrawOverlays()` 不可靠，判断是否授权以 `addView` 成功为准。没开就停在引导页，不报错。
4. 被拒绝时开关退回关闭，宠物页那一行显示「未授权」，点它重新引导。
5. vivo 和小米另有「后台弹出界面」权限。单击悬浮窗去拉起 Activity 时可能被拦，被拦就退回发一条可点的通知，做法照 `SystemActions.kt:263-268`。

## 14. 悬浮窗「问一句」、请求处理与语音（2026-10-30）

### 14.1 问一句和目标

长按菜单的首项打开单独的、仅在打开期间可获焦点的小输入窗。显示目标对话与主机，提供「新对话」切换；返回键、点窗外收起并保留草稿。IME 根据输入窗实际屏幕位置和局部重叠量抬升，重复 inset 不累计尚未布局的偏移；键盘消失后回到原停靠位置。

目标优先为宠物当前代表、位于当前主机、已知空闲且可用的对话；其他情况新建当前主机对话。宠物可能正在提示另一台仍连接的本机，此时不会悄悄切换全局主机。菜单中的「切换主机」供用户明确选择，SSH 仅列已固定主机指纹的主机，DSH Remote 仅列已信任的主机。

`askTarget` 创建 offer，绑定 host、connection、连接代次和 session；发送时重新验证。主机变化、重连、会话进入运行/审批/问题等待状态时拒绝发送并保留文本。新对话复用 `SessionsController.create`，再走 `ChatController.waitForSync/send`，保留正式聊天的历史、requestId 与同步语义。新建后发送失败的重试复用同一 session，不重复建空对话。

发送成功后由真实会话事件驱动 thinking/working；该轮完成的气泡显示经过掩码的回复开头（原生最多两行），点击打开完整对话。其他对话完成不泄漏正文；合并多个会话的气泡不显示单条回复。

原生输入草稿逐次保存到 App 私有 preferences。Flutter 未附着或没有 action handler 时，通过受保护的 `EntryActivity` 将文字交给前台新对话输入框，**不自动发送**。拉起失败时保留原生草稿；ROM 阻挡后台弹出时仍有现有通知入口。引擎未连接时输入窗明确提示，不直接拉起引擎或假装发送成功。

### 14.2 气泡审批和问题

批准只允许 `allowOnce` 与 `reject`，不提供「以后都允许」。原生按钮复用 `PromptInputPolicy`：出现后延迟启用、拒绝已知自动注入，保留 TalkBack 路径。之所以不按系统的遮挡标志（`FLAG_WINDOW_IS_OBSCURED` / `filterTouchesWhenObscured`）拒绝：悬浮窗在其他应用、横屏游戏或沉浸式装饰前时系统会误报遮挡，害得批准键在倒计时结束前完全按不动。Dart 使用通知的 `ChatAlertsController` 和原始 request，通过对应 host client 回答；host、root session、eventId、请求代次 token 必须全部吻合，撤回、重连或旧窗口上的按钮无法批准新请求。

只有完整、短小、没有秘密掩码和方向控制字符的工具名及 **全部 JSON 参数** 可批准；命令的 cwd、写入内容、替换文本不会只缩成文件路径。超过字符上限或实际气泡四行容纳不下时只能「去确认」。手机操控关键步骤继续使用已有 `PhonePrompt` 明确确认链路，不经桌宠简化审批。

单选问题只在一题、最多三个不重复的短选项、没有选项说明、详情或计划审查语义且题目完整可见时直接答。否则「去回答」进入聊天。选项换行显示，不截断后仍允许选择；自定义答案、多选与计划批准均留在聊天。

### 14.3 离线语音与前台降级

输入窗的麦克风按住录音、松开转写，滑出取消。录音沿用 `WavRecorder` 和 `MicArbiter`，音频只交给 **本机** 的 `sensevoice-local`、`host-local` provider；不会因为当前主机或语音默认选择变化而把音频交给远端或云 provider。模型未准备好时提示到 App 下载。

没有麦克风权限、录音启动被系统拒绝，或 Android 的 `AudioRecordingConfiguration.isClientSilenced` 表明后台录音被静音时，前台打开独立语音对话框。复用聊天的 `VoiceInputController`，强制本机离线 provider，不覆盖已有聊天草稿。识别完成或点击「返回桌宠」后把文本交回原生草稿，App 返回后台并重开输入条，仍须用户点击发送。

不新增权限或 microphone 前台服务类型：现有桌宠服务继续 `specialUse`，本机引擎服务声明不变。2026-10-31 在 API 35 x86_64 模拟器（App targetSdk 28）实测原生录音得到 47,660 字节 WAV，`configs=1 silenced=false`，桌宠前台服务类型为 `specialUse`；本地测试 Host 固定返回转写文本，验证了回填和用户确认发送，没有验证识别模型。API 34、OEM 后台政策和权限拒绝／静音后的前台降级仍未实测。验收必须记录：App 不可见时录音 service 类型、是否拿到音频/被 silenced、启动异常、前台权限授予、转写回填和返回桌宠；分别测试 API 34/35，勿把模拟器静音输入当作权限通过。
